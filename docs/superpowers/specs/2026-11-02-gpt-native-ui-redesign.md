# DSHA 全量 GPT 风格原生界面设计

## 意图

把当前只有 Web 聊天页接近 GPT 风格的诊断版，改成从启动、等待、聊天、设置、插件、
终端到诊断/错误状态都属于同一套产品界面。用户应当感觉自己始终在一个简洁的对话应用
里，而不是在“聊天皮肤”和“系统管理面板”之间跳转。

本次选择“全量原生重构”：重做界面壳层与共享组件，保留 DSHA 的服务、运行环境、
权限、插件、终端、备份、恢复和更新业务逻辑。diag2 的会话恢复修复必须原样保留。

## 目标

- 全部原生页面与 Web 聊天页使用一致的中性黑白灰视觉、字体层级、圆角、间距和动效。
- 手机、平板和横屏均有明确布局；不通过强制 `display` 或空白占位伪造侧栏。
- 主入口以“对话”为中心，运行准备和错误处理成为对话入口中的状态，而非独立控制台。
- 设置、插件、数据、设备授权、终端和诊断仍完整可达，危险操作与确认信息不被隐藏。
- 页面切换自然、加载状态有轻量动画，并尊重系统“关闭动画/减少动态效果”设置。
- 保留深色/浅色主题、中文/英文、无障碍触摸尺寸和现有功能状态。

## 非目标

- 不复制 ChatGPT 商标、图标、专有插画或品牌名称；仅采用同类信息架构和视觉语言。
- 不重写 Web/运行时、插件管理、权限、备份、终端或更新业务规则。
- 不在这轮新增账号、云同步、模型切换或新的服务协议。
- 不为追求外观而降低身份校验、会话恢复、停止围栏、维护屏障或日志脱敏强度。

## 反目标

- 不能出现平板被手机布局覆盖、手机缺少关键入口、横屏大面积空白或返回栈紊乱。
- 不能让加载动画掩盖真实卡住；状态文案、重试、详情和日志导出始终可访问。
- 不能把终端、权限同意、插件危险操作做成难以辨认的“漂亮按钮”。
- 不能靠逐页复制硬编码颜色与尺寸完成改造，否则后续页面会再次分裂。

## 方案比较

### 方案 1：全量原生重构（已选择）

新增统一 Shell、响应式导航和组件系统；现有 Fragment/Activity 保留业务事件，只替换布局
与容器。工作量最大，但能同时保证原生能力、可维护性和完整 GPT 风格。

### 方案 2：只替换主题和控件

改动小、风险低，但底部导航、卡片控制台和各自为政的动态页面仍然存在，不能达到“全改”。

### 方案 3：全部改成 WebView

最容易在视觉上统一，但终端、文件选择、系统权限、后台服务和恢复流程会变得脆弱，且增加
桥接攻击面，不适合 DSHA。

## 信息架构与响应式导航

### Activity 边界与默认进入行为

- 服务完成真实鉴权并确认可用后，默认自动进入 Web 对话；已经验证的恢复会话也直接进入。
  仅在停止、失败、恢复未知、需要权限/维护确认或用户明确关闭自动进入时停留在原生状态页。
- Web 对话继续使用独立的全屏 `WebPreviewActivity`，不嵌入原生 Shell。它复用同一主题令牌、
  系统栏和转场，但不叠加原生侧栏，避免破坏 WebView、文件选择、麦克风、画中画和返回栈。
- 备份、恢复、ADB、更新、技能、文件等独立工具 Activity 保留现有 Activity 边界和 Intent；
  全部换用 `GptTopBar`/`GptPage` 与统一转场。主目的地继续由 Shell 内 Fragment 导航承载。
  这样视觉上属于同一应用，同时不改动深链、任务栈和长流程生命周期。

### 主目的地

1. 对话：默认入口，包含欢迎、草稿、运行准备、恢复、进入聊天和最近状态。
2. 插件：插件列表、安装、启停、排序和来源。
3. 终端：PTY 优先，旧终端作为兼容回退。
4. 设置：运行环境、配置、数据与备份、设备授权、外观、更新、关于和诊断。

### 断点

- `>= 1024dp`：固定 272dp 左侧栏，右侧内容最大宽度按页面类型限制；聊天内容 800dp，
  设置/表单 760dp，终端可占满余下空间。
- `761–1023dp`：内容优先，侧栏改为可覆盖抽屉，不保留空的图标轨；顶部提供菜单按钮。
- `<= 760dp`：紧凑顶部栏 + 覆盖抽屉，内容单列；主操作可在安全区上方保持可达。

侧栏只负责导航和状态摘要，不复制完整聊天历史；现有 Web 历史栏仍由 Web 页面自己管理。
折叠状态由真实导航树决定，不用 CSS 强制显示不存在的内容。

## 视觉系统

### 色彩

- 浅色：背景 `#FFFFFF`，侧栏/次级区 `#F7F7F8`，悬停/输入 `#F1F1F1`，正文
  `#171717`，次要文本 `#676767`，分隔线 `#E7E7E7`。
- 深色：背景 `#212121`，侧栏 `#171717`，输入/卡片 `#303030`，正文 `#ECECEC`，
  次要文本 `#B4B4B4`，分隔线 `#424242`。
- 主操作在浅色使用近黑底白字，深色使用近白底黑字；蓝/绿只用于链接、进行中和成功状态，
  红色只用于故障与危险操作。

### 字体与间距

- 页面标题 22–24sp，区块标题 16–18sp，正文 15–16sp，说明 13–14sp。
- 采用系统字体栈，不嵌入第三方字体；正文行高约 1.45–1.6。
- 基础间距 4dp，常用节奏 8/12/16/24/32dp；触摸目标至少 48dp。

### 形状

- 普通列表容器 16dp，输入/主要操作 24–26dp，弹层 24dp。
- 减少“每一项都是边框卡片”：优先使用分组列表、留白和浅层背景；边框只表达层级或状态。
- 图标统一 20/24dp 矢量线性图标；禁止 Emoji 充当长期 UI 图标。

## 共享原生组件

新增或重构以下组件，页面不得各自硬编码样式：

- `GptShellLayout`：响应式侧栏、顶部栏、内容容器、系统栏和恢复横幅。
- `GptTopBar`：返回、菜单、标题、右侧操作，处理状态栏与横屏。
- `GptPage`：滚动内容、最大宽度、分组标题和可选固定底部操作。
- `GptSection` / `GptRow`：设置分组、图标、主副标题、尾部值/开关/箭头。
- `GptButton`：主要、次要、文字和危险四种语义。
- `GptStatusPanel`：准备中、已就绪、需处理、错误四类状态；保留详情与日志入口。
- `GptDialog` / `GptSheet`：手机优先底部弹层，平板使用居中弹窗；危险操作仍需明确确认。
- `GptLoadingIndicator`：轻量轨道/三点动画，不使用外部图片，不阻断状态更新。
- `GptEmptyState`：插件、任务、备份和文件列表的空状态。

现有 `CardPage`、`UiNavigation`、`DshaDialogBuilder` 和 XML 样式迁移到这些组件；迁移期可以
保留兼容适配层，但最终页面不得出现两套视觉。

## 页面设计

### 对话与启动

- 顶部只显示产品名、状态和设置/菜单入口。
- 中央欢迎区随状态变化：停止时显示“启动对话”；准备时显示动画、真实阶段和详情；就绪时
  自动进入或显示“继续对话”；失败时显示问题摘要、重试和查看详情。
- 草稿输入使用 26dp 胶囊输入框，保持 64 KiB 限制、防抖保存和已有附件/提交门禁。
- 诊断日志移入状态详情，但错误和未知恢复状态下必须直接可见。

### Web 聊天

- 保留 `chat-ui.css/js`，与原生颜色/间距令牌对齐。
- 消息与输入区最大 800dp；手机全宽留 12–16dp，平板居中。
- 宿主 1024px 抽屉断点和真实 collapsed 状态保持不变。
- 原生 Shell 在进入 Web 后只保留必要系统栏，不重复 Web 自身侧栏。

### 设置

- 设置首页使用 GPT 式分组列表；进入子页后使用统一顶部返回和内容宽度。
- 分组：运行与环境、数据与备份、设备与权限、外观与体验、更新与支持、诊断。
- 开关、当前值和说明保持原业务含义；高风险授权与维护操作不得缩写。

### 插件、终端及工具页

- 插件使用搜索/排序顶栏、扁平列表和状态标签；启停/删除行为不变。
- 终端内容保持深色高对比，Shell 只统一顶部栏、标签栏和安全区，不改变 PTY 生命周期。
- 备份、恢复、文件、ADB、无障碍、技能、后台任务和更新页全部通过 `GptPage` 迁移。
- 首次引导改为三步简洁说明；不隐藏必须由用户完成的权限或风险确认。

## 动效与状态

- 页面进入：160–220ms 的轻微淡入 + 8dp 位移；返回方向相反。
- 抽屉：标准滑入并带轻遮罩；弹层使用短距离上移。
- 加载动画不超过 1 个主视觉循环，同时持续显示真实阶段文本。
- 读取系统动画比例；为 0 或系统要求减少动态效果时关闭位移与循环，仅保留状态变化。
- 不为“自然”而预加载或重启服务；页面切换只改变视图，不改变运行状态机。

## 数据、错误与兼容

- 不改变 SharedPreferences、noBackup 记录、KeyStore alias、插件目录、备份格式或 Provider URI。
- 保留 diag2 对 `getNoBackupFilesDir()` 的规范化修复及全部会话恢复诊断。
- 旧页面保存状态和 Fragment 返回栈需要迁移测试；配置变更后不能重复启动服务。
- 更新包使用同一诊断签名、相同包名，版本提升为 diag3/code 192，可覆盖安装且保留数据。
- 原版 DSHA 与诊断版仍不可同时占用桥端口；界面需把该限制写清楚。

## 可访问性与本地化

- 所有图标按钮设置 contentDescription；状态使用 live region，但避免重复播报动画。
- 文字缩放到 1.3x 时不截断关键按钮；较长中文/英文允许换行。
- 键盘、方向键和 TalkBack 焦点顺序与视觉顺序一致。
- 颜色对比不依赖单一颜色表达成功/错误，状态同时有文字和图标。

## 测试与验收

- 共享组件单元/Robolectric 测试：断点选择、主题令牌、减少动画、按钮语义和状态映射。
- 布局测试宽度：360×640、412×915、800×1280、1024×800；检查侧栏/抽屉、内容限宽、
  文本截断、固定操作和返回入口。
- 页面覆盖：对话/启动四状态、设置首页及所有子入口、插件空/有数据、终端、诊断、更新、
  首次引导、错误与权限确认。
- 回归测试：现有定向测试、会话恢复、启动停止保护、草稿边界、插件操作和导航返回栈。
- 构建验收：ZIP CRC、无临时资源、ARM64、min/target SDK、versionCode、同签名覆盖和 16 KiB 对齐。
- 真机验收：先在目标 vivo/Android 16 覆盖安装；确认一次启动后再次打开能恢复，日志出现
  `WRITE_VERIFIED`、`SAVED`、`RESTORED`；再核对手机/平板/横屏截图。

## 实现者可自行决定

- 共享组件使用 XML、Java 自定义 View 或二者混合，只要不引入第二套 UI 框架。
- 具体矢量图标路径、动画插值器和测试辅助类命名。
- 迁移顺序，但应先建立令牌/组件/Shell，再迁移页面，最后调整 Web 皮肤。
