# DSHA 完整聊天界面改造设计

日期：2026-10-31。状态：待用户确认具体设计，尚未实现。

## 目标与范围

用户已选择完整界面改造：接近 ChatGPT 安卓版的聊天布局，隐藏面向用户的环境安装步骤和滚动日志。交付目标是可应用到 DSHA 源码的补丁包、中文使用说明和验证记录；本轮用户要求的是代码，不默认发布上游仓库或交付已签名 APK。

采用 DSHA 自身名称和标识，采用类似的简洁视觉与交互。模型、会话、工具、附件、设备权限仍使用 DSHA 的现有能力。聊天界面重构不更换模型提供商或处理用户账户。

## 方案选择

1. 轻量换肤：仅改颜色、字体和消息样式；无法满足隐藏安装流程及聊天优先入口的要求。
2. 完整改造：调整原生启动壳和现有移动聊天前端；保留已有运行、鉴权、存储与工具调用链。用户已选此方案。
3. 全新独立聊天客户端：重新实现会话协议及附件、工具审批等能力，成本与回归面更大。本次不采用。

## 页面设计

- 手机主页：顶部左侧会话抽屉按钮、中间模型入口、右侧新建聊天；主体为欢迎空态或消息流；底部为附件按钮、多行圆角输入框、发送/停止按钮。
- 消息：用户消息为柔和底色圆角气泡，助手回复采用正文排版；支持现有 Markdown、代码块、复制与流式回复。工具执行默认折叠为状态行，所需审批仍可见。只呈现后端实际支持的操作。
- 侧栏：新建聊天、历史会话、搜索入口（复用已有能力，必要时仅对已加载会话做明确标注的本地筛选）、设置。首次未就绪时显示历史加载状态，不能伪装成空历史。
- 设置：模型配置、外观、设备授权、插件、工作区、终端、数据备份、运行环境、诊断与关于。迁入的原功能保留可达入口。
- 平板：可用宽度达到约 840dp 时显示约 280dp 会话栏；消息内容最大宽度约 800dp。窄窗口、分屏退回抽屉布局，以实际窗口宽度决定布局。
- 外观：默认跟随系统深浅色，保留手动选择；中性背景、清楚的文字层级、足够触控面积；适配安全区域、字体放大和软键盘。

## 隐藏初始化的行为

启动后首先显示轻量聊天壳。首次正常安装在应用可见时发起已有受管环境准备；把原安装页和日志放到设置中的运行环境详情。准备时可编辑草稿，发送按钮禁用并说明原因，不排队自动发送。

状态必须来自真实任务与服务：检查环境 → 准备环境 → 启动服务 → 校验服务身份及网页鉴权 → 聊天可用。未配置模型时显示配置入口，不显示发送成功。界面恢复不等于服务就绪。

准备过程中仅显示一条简短状态，如“首次准备环境，可能需要几分钟”。进度来自实际回执；无法计算时使用不定进度，不编造百分比。Android 要求的前台服务通知和系统权限弹窗正常保留。

正常完成后只切换一次到原聊天前端，且不产生第二个聊天输入框或双层顶栏。优先复用现有网页与会话状态管理；输入过的本地草稿需要明确转移并读回确认，失败时保留原草稿，不自动发送。

失败、空间不足或初始化中断时显示可理解的原因、重试和查看详情。既有环境存在未完成维护或服务身份未知时，保留原环境与会话，等待核验或显式恢复，不用自动重装消除错误。用户停止后不因旋转、返回首页或重新渲染而自动重启。

“后台”指界面外的异步任务及已有合规服务，不承诺杀进程后继续安装或所有厂商息屏下稳定运行。

## 已核对的源码与实施边界

来源仓库：https://github.com/DSH-APP/DSHA ，2026-10-31读取默认分支；实际编码前固定具体提交并复核相关文件。

- `ui/MainActivity.java`：目前先检查欢迎状态，再调用入口门禁，必要时转 `ExtractActivity`。改为先展示聊天壳，仍保留恢复会话、环境维护和代次检查。
- `ui/WelcomeActivity.java`、`ui/OnboardingPrepareActivity.java`：目前为介绍及安装前页面。把必要说明迁入首次主页的简短提示和设置，不伪造环境已完成。
- `ui/ExtractActivity.java`：通过应用级 `BackupTask` 管理维护；已有 attempted_identity、taskId、pending 与失败记录。需提取可复用的准备协调逻辑，不能直接从新壳重复调用解压方法。
- `ui/FirstRunWebStart.java`：使用可见 Activity 申请 `HarnessService` 启动票据并等待提升后启动。新入口复用其保护模式，不直接绕过为后台启动。
- `ui/LaunchFragment.java`：目前用 `FirstRunWebStart.enqueueVisible` 发起启动并打开聊天入口；保留停止/取消语义，将详细运行管理移入设置。
- `ui/WebPreviewActivity.java`：已管理网页身份、保留实例、上传生命周期及鉴权恢复。优先在此基础上整合聊天壳与外观，不重写鉴权或替换为加载任意 URL 的通用浏览器。
- 现有移动前端来自受管 `dsh-web-mobile`；编码前确认实际源码与补丁入口，使用稳定组件/样式挂钩。不能靠猜测 DOM 选择器宣称完整兼容。

前端实际变更若涉及受管输入，须更新对应描述与摘要，并通过仓库已有构建验证；单纯界面更新不能误触发 Ubuntu 重建。现有系统授权、桥 token、设备命令策略、备份和凭据规则继续适用。

## 验证与交付

必须验证首次安装、已有环境、已有会话恢复、准备失败与重试、维护待恢复、未知服务身份、停止后返回、旋转/重建、网络失败、模型未配置，以及发送/停止、附件、工具审批、历史切换和设置入口。

布局覆盖 360/412dp 手机、横屏和 800/1024dp 平板窗口，深浅色、字体放大、键盘弹出。重点确认输入框无遮挡、只有一层顶栏、侧栏可关闭、失败时草稿不丢失。

交付包括补丁包、适用提交、应用与回退步骤，以及真实执行过的检查。具备依赖时执行 Java 关联单测、前端检查与 Standard Debug 构建；缺少离线输入、SDK 或真机时明确列出，不能把静态检查写成 APK 或设备测试通过。

默认先支持当前 Standard 路径；修改共享代码必须维持 Low 编译兼容，若无法验证 Low 则明确标注其未验证，不承诺完整 Low UI 功能。构建源码、签名与上游公开发布是独立事项，不由本设计默认授权。

## 留给实施者的决定

精确颜色、间距、图标、组件拆分和样式挂钩由实施者按上述交互选择；具体本地草稿转移接口需从现有前端核实。遇到必须重新实现会话协议、必须丢弃现有数据或无法保留工具审批的冲突时，应收缩实现并向用户说明，不悄悄改变设计。
